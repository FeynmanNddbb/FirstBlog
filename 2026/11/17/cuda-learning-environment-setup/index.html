CUDA学习笔记第一期——环境搭建

发表于2026-11-17|更新于2026-11-17|学习
|总字数:1.8k|阅读时长:6分钟|浏览量:

第一次接触CUDA时，最容易卡在“明明装了显卡驱动，为什么还不能编译CUDA程序？”这个问题上。GPU驱动、CUDA Toolkit、环境变量和编译器是几件不同的事，安装顺序也有讲究。

这篇作为CUDA学习笔记第一期，先把环境搭建这条链路跑通：装好驱动，安装Toolkit，验证nvidia-smi和nvcc，再编译一个最小的GPU程序。

先分清驱动和Toolkit

可以把GPU驱动理解成“让操作系统使用显卡的基础软件”，而CUDA Toolkit是“在这个基础上开发GPU程序的工具箱”。

驱动负责让系统识别GPU、管理显存和执行任务；Toolkit则提供nvcc编译器、CUDA Runtime、数学库、性能分析工具和调试器。只安装驱动，可以运行已经编译好的CUDA程序，但不能直接用nvcc编译.cu文件；只安装Toolkit，也不能代替驱动访问真实的GPU。

版本关系可以记住一句话：**驱动通常向前兼容旧版Toolkit编译的程序，但Toolkit不能反过来替代驱动。**每个Toolkit版本都有最低驱动要求，驱动版本达到要求即可，不需要和Toolkit的小版本号完全相同。

还要注意，nvidia-smi中的CUDA Version表示当前驱动最高支持的CUDA版本，不代表机器上已经安装了这个版本的Toolkit。真正查看nvcc版本，应使用nvcc --version。

命令 主要回答的问题
nvidia-smi 驱动是否正常，系统是否识别GPU
nvcc --version Toolkit和CUDA编译器是否可用
which nvcc或where nvcc 当前调用的是哪一份编译器

常见问题与排查顺序

遇到报错时，建议按“驱动→Toolkit→环境变量→编译参数→程序运行”的顺序排查：

现象 常见原因
nvidia-smi: command not found 驱动未安装，或命令路径没有加入PATH
driver/library version mismatch 驱动更新后没有重启，先执行sudo reboot
nvcc: command not found Toolkit未安装，或CUDA_HOME和PATH未配置
unsupported gpu architecture 当前Toolkit太旧，不认识目标GPU架构
cannot find -lcudart Linux下的LD_LIBRARY_PATH没有包含CUDA库目录
no CUDA-capable device 驱动、GPU识别或容器透传存在问题

还可以下载NVIDIA官方cuda-samples，编译deviceQuery进行完整检查：

如果最后出现Result = PASS，说明驱动、Toolkit和GPU之间的基本链路已经打通。CUDA 11.6之后，Samples通常需要从GitHub单独下载，不一定随Toolkit安装包提供。

写在最后

CUDA环境搭建的关键不是把所有组件一次性装满，而是确认每一层都能独立工作：先让nvidia-smi识别GPU，再让nvcc找到Toolkit，最后用一个小程序验证编译和运行。

后续学习Kernel、显存、线程层级和性能优化时，环境问题就不应该再成为主要障碍。记住这条顺序：装驱动，装Toolkit，配环境变量，编译程序，最后用deviceQuery复核。
